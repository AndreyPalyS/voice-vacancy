# Запуск, GitHub и развёртывание

## 1. Локальная установка

Установите Node.js 22.19+ и Git. Склонируйте публичный репозиторий:

```sh
git clone https://github.com/AndreyPalyS/voice-vacancy.git
cd voice-vacancy
npm ci
```

Скопируйте `.env.example` в `.env` (PowerShell: `Copy-Item .env.example .env`). Заполните только серверный файл:

```dotenv
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=qwen/qwen3.8-27b
PORT=4173
```

Создайте собственный ключ в https://console.groq.com/keys. Не добавляйте ключ в README, JS, коммиты, скриншоты или VITE_* переменные. Файл .env игнорируется Git. Не нужно шифровать и публиковать его: секрет хранится вне исходников.

```sh
npm run dev
```

Откройте http://127.0.0.1:4173. После изменения .env перезапустите сервер. `npm run preview` показывает только статику, поэтому для API используйте `npm run dev`.

## 2. Подключение AI

Фронтенд вызывает только собственные `/api/analyze` и `/api/generate-vacancy`; сервер обращается к Groq с секретом. AI оценивает конкретику пяти ответов и редактирует их в основу вакансии. Название берётся из первого ответа. Неизвестные факты остаются уточнениями.

Без ключа или при недоступности Groq приложение остаётся работоспособным и явно подписывает шаблонный режим. Это не ошибка сохранения: ответы не теряются. При 429 дождитесь обновления квоты. Текущие бюджеты: анализ 400, генерация 550 выходных токенов. Расширенный тариф может потребоваться при одновременной работе нескольких пользователей. Если модель недоступна, выберите поддерживаемую в своём аккаунте и задайте GROQ_MODEL; код настроен под режим reasoning_effort=none моделей Qwen.

## 3. GitHub и автоматические проверки

Основная ветка `main`. Workflow `.github/workflows/checks.yml` выполняет проверку секретов, Node-тесты, lint, TypeScript/build и браузерные сценарии. Для CI настоящий ключ не нужен: провайдеры подменены, локальный резервный режим проверяется отдельно. Не добавляйте GROQ_API_KEY в GitHub Actions без отдельной задачи на реальные интеграционные тесты.

Перед отправкой изменений:

```sh
git add <изменённые-файлы>
npm run check:secrets
npm test
npm run lint
npm run build
npm run test:browser
git diff --cached --check
```

`check:secrets` проверяет отслеживаемые файлы, запрет .env/логов и узнаваемые форматы ключей. Проверка не является гарантией отсутствия любых видов секретов. Перед первым push отдельно проверено точное значение локального ключа во всех Git-объектах. Если секрет всё же опубликован, немедленно отзовите его у провайдера: удаления файла недостаточно.

## 4. Sites

Sites размещает серверную Worker-версию. Конфигурация `.openai/hosting.json` связывает эту установку с конкретным Site. Для своей копии зарегистрируйте новый Site и замените project_id, не публикуйте в чужой проект.

В production runtime environment Site добавьте GROQ_API_KEY как secret и GROQ_MODEL как обычную серверную переменную. Значение ключа не должно попадать в manifest или архив. После изменения секретов разверните сохранённую версию заново.

```sh
npm run build:sites
```

Сборка создаёт `dist/server/index.js`, в котором UI-ресурсы встроены без .env. Worker обслуживает страницу и API, передавая runtime env общему сервису. Загрузка аудиофайлов в интерфейсе отсутствует, /api/stt в Worker не открыт. В публичном хостинге действует базовый лимит 4 API-запроса/мин на посетителя внутри экземпляра Worker, ограничение тела 128 КБ и проверка Origin. Это не глобальная биллинговая квота; для открытого массового использования добавьте централизованный лимит и наблюдение за бюджетом провайдера.

Демонстрационный Site открыт всем по ссылке по решению владельца. Новые копии Sites первоначально доступны только владельцу, аудитория настраивается отдельно. Публичность GitHub-репозитория сама по себе не меняет доступ к Site. Анонимные AI-запросы расходуют квоту владельца Groq.

## 5. Альтернативный хостинг

Адаптеры Vercel находятся в `api/*.ts`. Для собственного Vercel-проекта: framework Vite, Node.js 22, build `npm run build`, output `dist`, GROQ_API_KEY в серверных переменных окружения. Этот путь подготовлен, но отдельное размещение Vercel не проверялось. Для production до открытия доступа настройте квоты/защиту расходов.

GitHub Pages обслуживает статику и не запускает серверные API. Не кладите ключ в GitHub Pages или браузерный bundle. Для AI на Pages нужен отдельный защищённый backend.

## 6. Проверка после размещения

Пройдите пять вопросов, запустите полноту, соберите основу, исправьте предложение, скачайте .md и перезагрузите страницу. Проверьте микрофон с реальной речью и разрешениями. На мобильном и десктопе круг должен показывать 0..5. В DevTools клиент не должен отправлять Authorization с ключом Groq: он вызывает только собственный API.
