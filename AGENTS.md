# Правила разработки

Цель: сохранить короткий путь бизнес-заказчика к проверяемому черновику вакансии. Актуальный контракт в SPEC.md. Не расширять анкету без продуктового обоснования.

- Общие вопросы, валидация и шаблон: shared/domain.mjs. Общие облачные вызовы: shared/service.mjs. Не дублировать их в React и Vercel-функциях. Обновлять .d.mts при изменении экспортов.
- Не выдумывать зарплату, компанию, название роли, обязанности и процесс найма. Не маскировать шаблон под AI. Не называть словарную эвристику семантическим пониманием.
- Не включать микрофон автоматически. Один SpeechRecognition на mount, удаление обработчиков и abort при cleanup. Изменение callback не должно пересоздавать распознаватель.
- Не помещать ключи в VITE_* и клиентский bundle. Не логировать ответы, аудио, ключи или полные ошибки провайдера.
- Не запускать повторную генерацию из mount/effect. Не заменять отменённую операцию поздним результатом.
- Сохранять черновики при навигации. Любое удаление пользовательских данных подтверждать. Не исполнять HTML из ответов и моделей.
- Поддерживать 390px, видимый keyboard focus, подписи кнопок и reduced-motion. Не удалять текстовый резервный сценарий.
- Перед сдачей: npm test, npm run lint, npm run build, npm run test:browser. Для backend-контракта обновлять Node-тесты, для маршрута пользователя браузерные. Не объявлять реальные микрофон/Groq проверенными по мокам.
- Проверять затронутые экраны на скриншотах. Артефакты демонстрации в artifacts/. Актуализировать README, SPEC и DELIVERY по изменённому поведению.
